01

Cadrer avant de coder

Chaque chantier commence par une phase de réflexion en lecture seule : exploration du code, recherche, comparaison des options. Les décisions sont écrites avant la première ligne de code, puis transformées en plan.

02

Maîtriser le contexte

Règles chargées à la demande, sous-agents pour isoler les explorations et préserver la fenêtre de contexte, un worktree git par chantier. Un agent qui sait précisément où il est se trompe moins.

03

Des garde-fous déterministes

Des hooks bloquent les écritures hors périmètre, des règles interdisent les commandes sensibles, et les actions engageantes passent par une validation explicite. Le critique ne dépend pas de la bonne volonté du modèle.

04

Tester avant de relire

Les agents passent la qualité de code en boucle jusqu'au vert (analyse statique, linters, tests unitaires), puis testent les changements en conditions réelles : interface, API, tâches asynchrones, e-mails.

05

Une double revue

Revue agentique d'abord : plusieurs agents relisent le diff, chaque défaut est confirmé par une passe adverse. Revue humaine ensuite, sur ce qui compte : l'architecture, la sécurité, le métier.

Outillage

Skills et slash commands pour les gestes répétés, serveurs MCP, tests en conditions réelles pilotés par agent.

Ce qui reste humain

La conceptualisation du produit, les choix d'architecture, les arbitrages fonctionnels, et le pilotage d'une équipe d'agents qui travaillent en parallèle.
